# Public package: what is included, what is not, and why

Reproducibility classification applied to every artifact class in the working repository, using the
four-way scheme required for release review.

| Class | Meaning | Action |
|---|---|---|
| **A** | Essential and **not** regenerable | Deposit in full |
| **B** | Essential but deterministically regenerable | Represent by input manifest, command, software hash, environment and expected output hash |
| **C** | Derived / canonical | Include directly |
| **D** | Debug or temporary | Exclude |

---

## A — Essential, not regenerable: deposited in full

| Artifact | Size | Why class A |
|---|---|---|
| `data_manifest/` (23 files, 52 MB) — pool enumeration, eligibility, development and confirmatory cohort manifests, per-structure preparation manifests for all four variants | 52 MB | These capture the state of RCSB and SIFTS **as queried on 2026-09-15**, including residue-level construct ranges and the SHA-256 of each API response. RCSB re-releases SIFTS weekly and PDB entries can be obsoleted or superseded, so re-querying at a later date is **not guaranteed** to reproduce these annotations. This is the archival record of the cohort |
| `annotations/` — the three partner chimera indexes | 0.2 MB | Same reason |
| `PROTOCOL.md` and the three archived protocol versions, `DEVIATIONS.md` | 0.2 MB | The pre-specification itself; cannot be regenerated from anything |
| `environment/*.json` freeze manifests | 0.08 MB | Hash record of the frozen state |

## B — Essential but deterministically regenerable: represented, not deposited

| Artifact | Approx. size | Representation provided |
|---|---|---|
| Raw P2Rank and fpocket output trees for all four variants (`results/raw_detector/`, `results/confirmatory/*/raw_detector/`) | ~900 MB | `results/confirmatory/*/detector_runs.json` records, for every one of the 512 primary and every sensitivity run: the exact command line, detector version, input SHA-256, **output SHA-256**, stdout/stderr tail, return code and runtime. `results/RAW_OUTPUT_HASHES.tsv` records the SHA-256 of every output tree. Regenerate by re-running the detectors on the prepared inputs and compare hashes |
| Prepared detector inputs (`prepared/`, `prepared_confirmatory/`) | ~120 MB | Regenerated by `scripts/03_prepare_structures.py` / `20_prepare_variants.py` from the cohort manifests; each prepared file's SHA-256 appears as the `input_sha256` of its detector runs |
| Downloaded mmCIF cache (`.structure_cache/`) | ~1.5 GB | Fetched by PDB identifier from RCSB; **not redistributable as a matter of this project's policy**, and CC0 in any case. Identifiers are in the cohort manifests |
| P2Rank and fpocket distributions (`tools/`) | ~200 MB | Pinned version, release URL, git tag, commit and binary SHA-256 in `THIRD_PARTY.md` |

**Critical check.** *No headline value in the manuscript is read from a raw detector tree.* Every
reported quantity derives from `results/confirmatory/*/pockets_classified.json`,
`displacement.tsv`, `mechanism.json` and the canonical tables, all of which are class C and are
deposited in full. The raw trees are the input to the classification step only. A third party can
therefore verify every number in the paper **without** regenerating the 900 MB, and can
independently regenerate the 900 MB if they wish to verify the classification step itself.

> Following release-review guidance, hash-recording alone is **not** treated as sufficient for an
> inaccessible essential object. The raw trees qualify for class B only because everything needed
> to recreate them — inputs, commands, pinned software, environment — is included or precisely
> specified, and because no conclusion depends on them directly.

| Artifact | Why excluded |

## Third-party files present in the working tree but **excluded from the public package**

These are upstream objects, not this project's material. Redistributing them is unnecessary and, in
two cases, of unverified licence. Each is replaced by its identifier, source URL, byte size and
SHA-256 in `EXCLUDED_THIRD_PARTY.tsv`, and `scripts_release/fetch_third_party.sh` retrieves them.

| Excluded file | Bytes | Reason |
|---|---|---|
| `dataset_audit/membership/plinder_2024-06_v2_split.parquet` | 10,651,188 | Third-party corpus file; licence not verified by this project |
| `dataset_audit/membership/1dug_benchmark.pdb` | 156,249 | **Redistributed PDB coordinates.** This contradicts the project's own stated policy that no coordinate file is redistributed. CC0, so legally unproblematic, but unnecessary and inconsistent — removed for the public package and referenced by identifier instead |
| `dataset_audit/membership/*.ds` (9 files) | 191,867 | Third-party dataset membership lists; licence not verified |

**Consequence for freeze verification.** `environment/FINAL_FREEZE_v1.1.json` hashes the full
working repository, including these ten files. After running
`scripts_release/fetch_third_party.sh`, the retrieved files restore the tree to a state in which
the frozen manifest verifies completely. Until then, a manifest check against the public package
will report those ten paths as absent — expected, and documented here rather than hidden.

## Local paths and execution identifiers in frozen records

Frozen execution records retain local scratch paths (`C:\Users\user\AppData\Local\Temp\claude\...`) and opaque execution identifiers verbatim. They are non-sensitive run provenance, contain no credential of any kind, and are hashed in `environment/FINAL_FREEZE_v1.1.json`; redacting them would break the reproducibility hashes. See README section 15 and `RELEASE_QA.md` section 2.
